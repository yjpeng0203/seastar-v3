# 树莓派只读转发、工控机接收与分析

状态：增量接收、接收水位和故障恢复已经实现。工控机部署步骤见 [DEPLOY_IPC.md](DEPLOY_IPC.md)。不需要在树莓派安装本包；树莓派原 DAQ 和 fee-monitor 保持原状。

```text
树莓派 DAQ → 原始 DAT（保留现有写入）
                 ↓ 单 OpenSSH 长连接，临时只读 Python 助手
工控机 DAT 镜像 → 接收事务水位 → 自适应分析 / SQLite → 浏览器 :8766
```

## 已实现的接收规则

- 默认只接收匹配 FEE 的最新 Run，不回扫全部历史；随后发现的新 Run/分卷自动接收。可显式选择 `start_mode: all`。
- 仅顺序读取新增字节。默认每块最多 256 KiB、新增数据限速 2 MiB/s、追平后每秒检查活动文件；文件名和元数据默认每 10 秒扫描。新卷发现延迟受此扫描间隔影响。
- 保留原文件名、Run 和分卷关系。树莓派文件以只读方式打开，优先 O_NOATIME；Python 使用 -B，不生成字节码；尝试降低助手自身优先级。不在树莓派保存助手、进度、数据库或待发送副本，不压缩，不反复进行整卷哈希。
- 接收盘先写文件并 fsync，再以 SQLite FULL/WAL 事务推进接收水位。分析端只读已提交前缀，不能把崩溃前未提交的尾部提前累计。恢复仅移除接收器自己的未提交尾部，不回退已提交数据。
- 接收器与分析器分别保存检查点。网络中断按 2、4、8…最多 60 秒退避重连；从已提交字节位置继续。正常连接内不重复下载已接收内容；重连时只额外读取少量头尾边界校验。
- 源文件须为不可回写的追加文件。身份更换、截短、边界改变、已切换旧卷再次增长或原文件消失会停止并告警，不覆盖本地历史。不能检测保留身份和边界的任意恶意中间改写。
- 工控机空间低于预留阈值（默认 2 GiB）时暂停接收。源盘空间显示并告警；树莓派原文件永不自动删除，不能承诺无限期断网仍有足够缓存。
- 密码启动时输入一次，仅由工控机进程内存与私有本地 socket 提供给系统 SSH。配置、命令行、环境变量和数据库中不保存密码。错误密码只试一次后停止，严格核对主机密钥；不处理密码过期修改或 MFA。密钥/agent 模式也可使用。

## 稳定性与 SD 卡边界

本方案减少新增监控负担，不消除 DAQ 原有 SD 写入。树莓派仍有顺序读取、SSH 加密及系统认证日志等开销；操作系统交换/缓存行为由现场配置决定。若长期采集写入量大，仍建议评估外接 SSD。

网络慢、接收停止或分析变慢不会调用 DAQ 的停采/改写接口。Pi 本地文件是补传依据；但空间最终可能填满，因此应监控积压及源盘余量。限速要结合实际产数速率，长期传输能力不足会持续积压。

504 点波形为 1008 字节采样值，加 16 字节波形头，另有触发头。1000 条/秒约 1 MB/s，10000 条/秒约 10 MB/s。应实测峰值写入与有效网络速率，不用全程平均值代替峰值。

默认 rsync 的目标文件替换方式不适合本接收器跟踪增长文件；本实现直接追加且按提交水位隔离。[rsync 官方说明](https://download.samba.org/pub/rsync/rsync.1)
