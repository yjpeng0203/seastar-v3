# decode 调用修复

## 对照现场命令

现场工作目录为 `/home/ipc/disk/debug/data/both`，可运行的命令形式为：

```sh
../../build/decoder input.dat output.dat.root --config ../../cfg/config.json
```

本项目原先的参数顺序和工作目录正确，但默认 `decoder_config` 误写为 `../cfg/config.json`，会指向 `/home/ipc/disk/debug/data/cfg/config.json`；现场文件实际位于 `/home/ipc/disk/debug/cfg/config.json`。原集成检查也沿用了错误的目录层级，本次已同步修正。

## 修复内容

- 默认配置路径改为 `../../cfg/config.json`，与现场命令一致。
- 兼容既有配置文件：旧值恰为 `../cfg/config.json`、该路径不存在且正确位置确有配置时，输出明确警告并使用正确位置。不改写现场 JSON。
- 已存在的旧路径、显式自定义路径和绝对路径保持原有配置含义，不进行泛化路径搜索。
- `organizer check` 显示实际 decoder 程序及配置绝对路径。
- `organizer watch` 在打开增量状态库前检查后端，配置缺失立即报错退出。
- 输入 DAT 只读；临时 ROOT 完成并通过原有事件数、首末触发及分支校验后原子发布。自动检查点仍写入 work_dir/parts，不改变原始目录。

## 升级包

`seastar-v2-decode-fix-20261106.tar.gz` 为 decode 专用修复包，包含 organizer/config.py、organizer/cli.py、相关检查与本文。不会覆盖 `config/ipc.json`、现场示例配置、DAQ 的 cfg/config.json、监视器代码、断点数据库或原始 DAT。完整安装包中的示例配置也已更新。

先停止旧的 organizer watch；若使用联调启动脚本，结束该脚本，DAQ采集进程继续运行。将修复包放到 ~/SeastarMonitor_pyj 后执行：

```sh
cd ~/SeastarMonitor_pyj
tar -czf "organizer-before-decodefix-$(date +%Y%m%d-%H%M%S).tar.gz" -C seastar-v2 organizer
tar -xzf seastar-v2-decode-fix-20261106.tar.gz
cd seastar-v2
cfg=config/ipc.json
[ -f "$cfg" ] || cfg=config/ipc.example.json
python3 -m organizer check --config "$cfg"
```

自检中应看到：

```text
decoder 程序 : /home/ipc/disk/debug/build/decoder
decoder 配置 : /home/ipc/disk/debug/cfg/config.json
```

若既有 JSON 仍使用旧默认值，兼容警告会说明实际采用的路径。若自检显示另一个确实存在的自定义配置，则保持自定义设置；需要按截图运行时，将所用 JSON 的 organizer.decoder_config 明确设为 `../../cfg/config.json`。

随后恢复原启动方式：

```sh
sh scripts/start_ipc.sh
```

自动 decode 日志为 `runtime/ipc/logs/organizer-watch.log`。按示例配置，单卷 ROOT 检查点位于 `/home/ipc/disk/debug/data/organized/.organizer_work/parts/<run>/`，不会直接出现在原始 both/ 列表里；停采后 finalize 再合并到批次的 Gx/rec_data/。

采集期间 watch 处理已封卷，当前正在写入的末卷保留给后续封卷或停采 finalize，不强制读取未完成尾记录。
