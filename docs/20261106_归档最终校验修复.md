# 文件已生成，但最终校验报错

## 截图对应的阶段

归档按“解码→DAT副本→ROOT合并→CSV切片→清单和SHA→最终核验”执行。截图中 G3/G4/G5、ROOT、CSV、manifest.json 和 SHA256SUMS.txt 已生成，说明流程已经走到最终核验。

错误 `macro /tmp/seastar_verify_.../inspect_seastar_....C not found` 指向校验用的临时 C++ 宏，不是说归档 ROOT 文件不存在。ROOT 没有读到文件，旧版校验器却继续把未读出的 ROOT 事件累计值0与DAT比较，造成额外的“0事件”报错。这不能证明文件为空或损坏，也不能仅凭文件存在与大小宣布归档完整。

## 修复

- 最终批次校验的宏改放到归档工作目录，与已成功的单卷/合并校验一致，不再依赖 Python 系统 /tmp 与 ROOT 运行环境共享。
- ROOT未全部读出时不比较事件总数，不产生误导性的“0事件”错误。
- ROOT报错改为“校验未通过”，保留校验工具的具体失败原因。
- 若文件已生成但最终核验失败，网页明确显示“已生成文件 · 最终校验未通过”及结果位置；状态保持失败，不保存为成功任务记录。

## 更新

使用 `seastar-v2-archive-verify-fix-20261106.tar.gz` 覆盖已部署的网页归档版。先结束旧监控服务，DAQ采集程序保持运行；配置、数据、分卷检查点和已生成归档均保留。


浏览器 Ctrl+Shift+R 刷新。原批次先保留，不要删除 DAT、ROOT、CSV 或 .organizer_work。重新选择原 Run 并归档时，会复用已通过的分卷解码检查点；仍会执行必要的合并、CSV和最终验证。只有最后验证通过，网页才显示“归档完成”。“检查环境”按钮检查程序与路径，不等同于重新核验已生成批次。
