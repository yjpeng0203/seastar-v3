## 4. 封卷转换与归档

仅对抽样副本操作：将每串副本在触发边界拆成两卷，置于调试目录的独立平铺输入目录。

1. `watch_once`：每串仅转换第一卷，共转换 3 卷，保留 3 个活跃末卷。
2. `finalize_session`：复用 3 个首卷缓存，新增转换 3 个末卷；每串通过真实 `hadd` 合并两卷 ROOT。
3. 归档输出 G3/G4/G5 的 raw_data、rec_data、csv，以及 manifest.json、SHA256SUMS.txt。
4. 三串分别得到 3,801/3,765/3,797 个 ROOT 事件，各 4,036 条波形；CSV 切片分别为 110/108/106 行。
5. 对新归档执行包含 SHA-256 的完整 verify，通过。
6. 重复执行 finalize，返回 `nothing_to_finalize`。

测试使用本机 PyROOT 后端和 ROOT hadd；现场 IPC 外部 decoder 路径由现有模拟 IPC 测试覆盖，本次未连接现场机器。没有重新打包或覆盖原始 20261101_1102 数据集。

## 5. 已修复问题

**慢控制本地模式切串后，旧串文件被误列为“暂时不可用”。**

复现：从 G5 切到 G3，文件选择框仍添加 G5 的文件，并标为缺失；实际只是被串筛选排除。原因是 `renderFileOptions()` 对所有不在可见列表中的当前文件都补缺失选项。

修复：仅当当前文件属于所选串、没有串过滤或处于远程模式时保留缺失选项。真实缺失文件提示仍保留。

修改文件：`fee-monitor/app.js`；回归用例：`fee-monitor/tests/test-chart.cjs`。修复后在浏览器切换 G3/G4/G5，文件列表只保留当前串文件。
