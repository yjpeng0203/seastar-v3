# 实时监控排队修复

## 现场现象与直接原因

混合数据目录含旧 FEE7/FEE8、新 G3/G4/G5、历史 ROOT 和 `trigger_signal_*.dat`。默认 workers=3 时，旧 FEE7/FEE8 即使已暂停，仍被父调度器计入活动任务，加上 G3 后占满名额，G4/G5 持续排队。旧串按组名字排序，又可能优先于新 DAT 启动。选中排队串时页面显示“正在启动”，并可能保留上一串通道控件。

## 修复

- 暂停任务释放分析名额，服务与查询端口保留；恢复/重算操作遵守上限，并保留启动预约避免并发命令超额。
- 在线启动优先最新 DAT；历史 ROOT 后排。回放模式仍优先 ROOT。
- 发现波形源时排除 `trigger_signal_*.dat` 旁路文件；波形帧解析及数值内核不变。
- 排队串显示“等待计算资源”，返回选中的源，清空通道控件；排队/启动期间暂停按钮禁用。
- 加入上版数据后端的检查点兼容项，仍要求内核 SHA256 和状态版本一致。更新时保留原 state-dir。

## 验证

本机波形监视器 Python 全部53项检查通过；前端3组检查通过。

另外通过实际HTTP服务和三个独立原生分析进程，读取三串各4 MiB真实DAT样本副本。在含旧FEE7/FEE8、历史ROOT、trigger_signal旁路文件的混合目录中，每串读入4036条波形，追加后为4037条；自动跟随新Run后各读入4036条。各串8通道，切换查看和新Run跟随均保持原工作进程PID。

针对现场新增回归：

1. 旧板 FEE7/FEE8 暂停后，新 G3/G4/G5 在 workers=3 下均开始读入；旁路文件未创建额外任务。
2. 同时分析数保持不超过3；满额时继续旧任务给出明确提示。
3. 三串跟随新 Run，并在半包补全后继续分析。
4. 排队串返回自身源与空通道，页面清除旧通道控件。
5. 上版检查点恢复原会话、计数和偏移，追加数据恰好消费一次。

工控机程序尚未更新，本版本由用户自行部署后进行现场验收。

## 工控机更新

1. 在运行8766监视器的终端按Ctrl+C结束监视器，采集进程继续运行。
2. 已安装上版时，推荐将升级包 seastar-v2-monitor-fix-20261106.tar.gz 放到 ~/SeastarMonitor_pyj。该包更新监视器代码、说明和回归检查，不覆盖配置、原始数据或断点目录。执行：

```sh
cd ~/SeastarMonitor_pyj
tar -czf monitor-code-beforefix.tar.gz -C seastar-v2/data-ana-monitor/online fleet.py acquisition.py server.py static/app.js
tar -xzf seastar-v2-monitor-fix-20261106.tar.gz
```

3. 你当前使用联调启动脚本，可执行 `cd ~/SeastarMonitor_pyj/seastar-v2`，再执行 `sh scripts/start_ipc.sh`。若原来使用独立波形启动命令，继续沿用原 data-dir、state-dir 和 workers=3；不要同时启动两套8766服务。浏览器Ctrl+Shift+R刷新。
4. 观察G3/G4/G5波形数随DAT追加增长，切换串后仍持续读取，侧栏不再因暂停旧任务而长期排队。

默认没有删除旧会话、缓存、原始DAT或配置。

完整安装包仍为 seastar-v2-ipc.tar.gz；现场已安装上版时优先使用上述升级包，避免覆盖本机修改过的示例配置。备份文件 monitor-code-beforefix.tar.gz 应保留，重复更新前先改名以免覆盖上次备份。
